# P6. 브라우저 없이 규칙 확인하기 — `p6: check`

P4 에서 규칙이 맞는지 보려고 표의 숫자를 하나씩 눈으로 대 봤습니다. 예보는 매일 바뀌어서, 오늘 표에 "기준과 정확히 같은 날" 이 없으면 그 경우는 확인할 수조차 없습니다.

`logic.js` 는 순수 함수만 있어서 브라우저 없이 Node 로 바로 돌릴 수 있습니다. 확인하고 싶은 경우를 **입력을 직접 만들어서** 돌려 봅니다.

파일: `check.js`

## 만들 것

1. `check.js` 에서 `logic.js` 의 `toDays`, `isGoodDay`, `summarize` 를 import 합니다.
2. Open-Meteo 응답의 `daily` 와 **같은 모양**의 객체를 손으로 만듭니다. 4일 이상, 날짜는 아무거나(`"11-21"` 처럼) 괜찮습니다. 기준은 `{ rain: 30, wind: 10 }` 으로 둡니다.

   참고: 44장(Check the Rules Without a Browser)의 `daily`. **슬라이드와 다른 점**: 키 이름이 오늘 받는 세 필드(`temperature_2m_max`, `precipitation_probability_max`, `wind_speed_10m_max`)여야 `toDays` 가 읽습니다.

3. 값은 아래 경우가 **전부 들어가게** 고릅니다.

   | 경우 | 무엇을 확인하나 |
   |---|---|
   | 강수·풍속 둘 다 기준 아래 | 보통의 좋은 날 |
   | 강수 = 30, 풍속 = 10 (둘 다 기준과 정확히 같음) | "이하" 를 제대로 썼나 |
   | 풍속만 기준을 넘음 | 두 조건을 다 보나 |
   | 강수만 기준을 넘음 | 〃 |

4. `console.log` 로 아래를 찍습니다.
   - `toDays` 의 첫째 날 객체
   - 각 날의 `isGoodDay` 결과
   - 그 날들의 `summarize` 결과
   - **빈 배열** `[]` 의 `summarize` 결과
5. 각 `console.log` 줄 오른쪽에 예상 결과를 주석으로 적습니다. **실행하기 전에** 적습니다. 실행한 뒤에 출력을 베껴 적으면 확인이 아닙니다.
   ```js
   console.log(isGoodDay(days[1], limits)); // true (둘 다 기준과 같음)
   ```

   참고: 45장(Questions Every Rule Must Answer). **슬라이드와 다른 점**: 슬라이드는 입력과 확인할 경우를 정해 주고 출력을 터미널 박스로 따로 보여 줬습니다. 오늘은 3번 표의 경우가 다 들어가게 값을 직접 고르고, 예상 결과를 코드 옆 주석으로 먼저 적습니다.
## 확인 (터미널)

6. `oss-week09` 폴더에서 실행합니다. 서버를 켠 터미널이 아니라 다른 터미널에서 합니다.
   ```
   node check.js
   ```
7. 출력이 한 줄에 하나씩 나옵니다. 첫 줄은 이런 모양입니다(값은 내가 넣은 것).
   ```
   { date: '11-21', max: 12, wind: 6.2, rain: 10 }
   ```
   나머지 줄을 주석의 예상과 하나씩 대조합니다. **값이 전부 같으면** 끝입니다. Node 는 문자열을 작은따옴표로, 배열을 `[ 'rain' ]` 처럼 띄어 찍습니다. 주석의 따옴표 모양이나 띄어쓰기가 달라도 값이 같으면 같은 것입니다.
8. 다르면 둘 중 하나가 틀린 것입니다. P4 의 규칙 표를 기준으로 어느 쪽인지 판단합니다.
   - 예상이 틀렸으면 주석을 고칩니다.
   - 코드가 틀렸으면 `logic.js` 를 고치고, 브라우저에서도 P4 의 확인을 다시 합니다.
   - `document is not defined` 같은 오류가 나면 부록 E10.

## 커밋 (터미널)

9. 커밋하고 push 합니다. `logic.js` 를 고쳤으면 같이 넣습니다.
   ```
   git add check.js
   git commit -m "p6: check"
   git push
   ```
